# autosport_sim

Менеджер автоспорта: Formula, GT и гонки на выносливость в общем мире. Три определённые роли — менеджер команды, владелец гоночной организации и производитель двигателей/коробок передач.

## Приложение

APEX открывает 11 разделов на русском языке в демонстрационном режиме. Начальная роль — менеджер VANTA Racing. Для перехода в организацию или производство смените роль в боковом меню. На телефоне оно открывается кнопкой «Ещё». Формула, GT и выносливость выбираются в штабе или чемпионатах. Изменения действуют до обновления страницы.

### Windows — двойной клик

1. Один раз установите [uv для Windows](https://docs.astral.sh/uv/getting-started/installation/) версии 0.13.9 или новее и [Node.js 24 LTS с npm](https://nodejs.org/). Также поддерживается Node.js 22 LTS от 22.13. Нужен npm от версии 9. При первом запуске uv найдёт совместимый Python (3.11–3.14) и при необходимости загрузит его.
2. В Проводнике дважды нажмите **start.bat** в корне репозитория. При первом запуске нужны интернет и доступ на запись в папку игры. Окно покажет версии инструментов, подготовку окружения и сборку. Браузер откроется после ответа API и загрузки собранного интерфейса через локальный сервер.
3. Оставьте окно запуска открытым во время игры. Ещё один двойной клик по **start.bat** откроет работающий экземпляр. Пока идёт подготовка, достаточно дождаться первого запуска.
4. Для остановки дважды нажмите **stop.bat** или закройте окно запуска. Закрытие одной вкладки браузера оставляет игру запущенной.

При обычном запуске зависимости устанавливаются автоматически. uv сверяет окружение с `uv.lock`. Клиент повторяет установку при изменении манифеста, lock-файла, среды Node/npm или отсутствии установленных инструментов. При каждом новом сеансе интерфейс собирается из текущих исходников. Локальные серверы предпочитают порты 8102 и 5173. Если порт занят, запуск подбирает свободный и показывает адрес в окне. При ошибке окно остаётся открытым.

Запуск двойным кликом по корневому **start.bat** — обязательное требование для последующих версий проекта.

### Linux и ручной запуск для разработки

Потребуются Python 3.12, [uv](https://docs.astral.sh/uv/getting-started/installation/) и Node.js 24 LTS с npm. Используйте два терминала в корне репозитория. Команды одинаковы для PowerShell и Bash.

В первом терминале установите Python-зависимости из `uv.lock` и запустите API.

```sh
uv sync --locked --python 3.12
uv run --locked uvicorn backend.app:app --host 127.0.0.1 --port 8102
```

Во втором установите клиент из `package-lock.json` и запустите Vite.

```sh
cd frontend
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

Откройте [приложение](http://127.0.0.1:5173). Vite проксирует `/api` на порт 8102. Состояние сервера доступно в [health](http://127.0.0.1:8102/api/health), режим интерфейса — в [config](http://127.0.0.1:8102/api/config).

Для просмотра production-сборки оставьте API запущенным и выполните из `frontend` следующие команды. [Открыть собранное приложение](http://127.0.0.1:4173).

```sh
npm run build
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort
```

### Проверки

Из корня репозитория:

```sh
uv run --locked ruff check backend
uv run --locked python -m pytest -q
```

Из `frontend`:

```sh
npm run lint
npm run typecheck
npm run build
npx playwright install chromium
npm run smoke
```

Smoke запускает API и preview при необходимости, затем проходит одни и те же сценарии в desktop и мобильном touch-контексте. На минимальной Linux-системе для установки системных библиотек браузера поддерживается `npx playwright install --with-deps chromium`. Для уже установленного Chromium можно пропустить загрузку браузера и указать путь к исполняемому файлу.

```sh
# Bash
CHROMIUM_PATH=/usr/bin/chromium npm run smoke
```

```powershell
# PowerShell, если Google Chrome установлен в стандартном каталоге
$env:CHROMIUM_PATH = "$env:ProgramFiles\Google\Chrome\Application\chrome.exe"
npm run smoke
```

## Запустить интерфейсный эталон

Из корня репозитория:

```bash
python -m http.server 8080 --directory reference/ui-v1/dist
```

На Windows можно использовать `py` вместо `python`. Открыть `http://localhost:8080`. Это запускает исторический интерактивный макет, отдельно от React-приложения. Для макета не требуется npm install: ассеты и зависимости сохранены рядом.

**Актуальное изменение:** пользователь отклонил мультяшный 3D-болид. В продукте v1 нужен фотореалистичный боковой 2D-вид с редактируемой ливреей и спонсорами. Старый 3D в локальном макете сохранён только как часть исторического снимка; не переносить его в приложение. Остальные 11 экранов, мрачная палитра, плотность и мобильная композиция остаются визуальной основой.

Подробнее: [reference/ui-v1/README.md](reference/ui-v1/README.md).

## Принципы

Законченный интерфейс с первого этапа, постепенное подключение доменной логики, единые сохранения, объяснимые результаты, навыки 0–100 и действующие трейты. Гонка — 2D-карта и управление стратегией. Деньги и результаты учитываются по устойчивым ID и не применяются повторно при retry/save/load.

Проект не требует мультиплеера, LLM, реальных платежей или лицензированных команд. Лицензия проекта — [MIT](LICENSE); лицензии сторонних библиотек/шрифтов и происхождение изображений описаны в [каталоге ассетов](docs/DEMO.md#ассеты-и-происхождение).


## Актуальное решение: реальные данные и локальный пакет изображений

Начальная карьера основана на реальном автоспорте выбранного сезона (по умолчанию последний сезон с достаточными проверяемыми данными). Первая очередь: F1/F2/F3, GT3 и WEC; IndyCar и Formula E предусмотрены как последующее расширение регламентов, не обязательны для #3. Реальные команды, пилоты, доступный публичный персонал, поставщики, трассы, календарь и правила с источниками и датой среза. Не выдумывать неизвестные контракты или технические данные как факты: игровые оценки навыков 0–100, потенциала, трейтов и закрытых параметров явно маркировать. После старта мир развивается автономно, включая вымышленных новичков и новые организации. Исторический UI-эталон остаётся демонстрацией.

Codex должен подготовить отдельный ZIP с реальными логотипами и фотографиями из доступных правомерных источников для ручного локального импорта (не публиковать защищённые изображения в Git, PR, releases или публичных CI artifacts). Если права или доступ не позволяют включить файл, указать источник и пробел, не подменять фото вымышленным. Пакет содержит manifest с версией, стабильными ID сущностей, типом ассета, путём, источником, лицензией/условиями и SHA-256. Импорт через UI или документированную локальную команду, с проверкой схемы, размера, формата, путей ZIP (без traversal/symlink), атомарным применением и повторным импортом без дублей. Локальные пакеты и импортированные файлы исключить из Git; без пакета приложение работает с нейтральными заглушками. Не требовать платных API или скачивания изображений при каждом запуске. Подготовить ZIP вне репозитория и передать пользователю приватно, если среда позволяет; иначе предоставить локальный сборщик и точную инструкцию, явно указав, что архив не передан.
