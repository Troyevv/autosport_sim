# AGENTS.md — autosport_sim

## Цель проекта

Однопользовательский менеджер автоспорта с общим миром Formula, GT и гонок на выносливость. Игрок управляет командой, владеет гоночной организацией либо производит двигатели и коробки передач. Название APEX, VANTA, сезон 2028 и персонажи макета — демонстрационные данные, а не окончательный бренд; реальные серии используются в карьерных данных.

Общаться с пользователем и писать описания задач/PR по-русски. Код и технические идентификаторы — на английском. Не объявлять демонстрацию готовой игровой системой.

## Что читать перед работой

2. `docs/PRODUCT.md` — действующие продуктовые решения.

4. `docs/ROADMAP.md` — порядок задач и границы этапов.
5. `reference/ui-v1/README.md`, затем запустить локальный эталон и посмотреть затрагиваемые экраны.

Прямое актуальное указание пользователя важнее старых документов и демоданных. Исторические файлы внутри `reference/ui-v1/docs` описывают старый макет; при конфликте использовать действующие `docs/PRODUCT.md` и этот файл. Не изменять инструкции ради обхода требований. Если обнаружен настоящий конфликт, объяснить его и выполнить всё, что не заблокировано им.

## Обязательные продуктовые решения

- Законченный, плотный и читаемый интерфейс на русском; desktop и телефон обязательны. «Сначала простой MVP, потом красивый интерфейс» не является допустимой подменой задачи.
- Визуальная основа — весь макет, а не только гараж: графитовый фон, сдержанный красный, строгие панели, согласованная типографика, понятные таблицы и действия.
- Всего три определённые роли: менеджер, владелец, производитель двигателей/коробок. Четвёртая роль пока не определена; не придумывать и не добавлять её автоматически.
- Formula, GT и Endurance — разные регламенты одного мира. Люди могут переходить между дисциплинами; их идентичность, история, контракт и освоение дисциплины сохраняются.
- Навыки пилотов и персонала — от 0 до 100. Есть индивидуальные положительные, отрицательные и ситуационные трейты, включая временные с датой окончания. Общий рейтинг не заменяет профиль навыков.
- **Гараж v1 — качественное фотореалистичное изображение машины строго сбоку с редактируемой ливреей.** Сохранить тёмный гараж и верхние прожекторы. Мультяшные процедурные 3D-модели из старого прототипа пользователь отклонил. Не переносить их в продукт и не возвращать WebGL/Three.js как обязательную зависимость.
- Ливрея: отдельные данные цветов, зон/узоров, номера и логотипов; перекраска через маски с сохранением света и тени. Шины, стекло и фон не окрашиваются вместе с кузовом. Для будущего 3D допускается новый renderer, а не переписывание контрактов ливреи.
- Гонка — полноценный 2D-экран управления с картой, таймингом, стратегией, пит-стопами и радио. Графическая простота не оправдывает случайные результаты без симуляции.

## Границы реализации

Работать по одной issue или явно согласованной группе. Не пытаться закрыть весь эпик за один PR. Поэтапное подключение систем разрешено; деградация дизайна и ложные заявления о готовности — нет.

В исходной задаче оболочки разрешён **явно обозначенный демонстрационный адаптер**. Он не является карьерой, не выдаёт фиктивное сохранение за настоящее и не смешивается с будущей SQLite-базой. После появления доменных команд соответствующий экран использует их, а не вторую локальную копию состояния. Остаточные демонстрационные обработчики должны быть перечислены в PR.

Не добавлять без отдельной задачи мультиплеер, авторизацию, платежи, облачную инфраструктуру, LLM для симуляции, дополнительные профессии или публичное распространение защищённых ассетов. Не расширять область изменения соседними рефакторингами.

## Архитектура и качество

- Начальная основа: Python + FastAPI + SQLite, React + TypeScript + Vite. Модульный монолит; симуляция — чистый Python без зависимости от HTTP, браузера и БД. Конкретные совместимые версии фиксируются lock-файлами при bootstrap.
- Единое авторитетное состояние карьеры и единые доменные команды. UI отображает результаты, не вычисляет параллельно бюджет, места, очки или последствия контрактов.
- Отделять domain, application services, persistence/API и UI. Достаточно реальных модулей; не строить микросервисы, собственный ECS, универсальный plugin framework или event-sourcing платформу без необходимости.
- Seed и состояние генератора случайности сохраняются. Одинаковые входы/команды/версия правил воспроизводят симуляцию. FPS и скорость отрисовки не определяют результат гонки.
- Деньги хранить целыми минимальными единицами валюты с явной единицей в API. Операция, проводки, изменения контрактов и контрольная точка сохраняются атомарно.
- Повторная команда с тем же идентификатором не списывает деньги, не подписывает договор, не завершает гонку и не начисляет очки повторно. Команды одной карьеры не должны гоняться друг с другом.
- Результат гонки связывать по устойчивым ID машины/заявки/пилота/команды. Нельзя использовать экранную позицию, индекс строки, имя или цвет вместо идентичности.
- Сохранение содержит версию схемы, игровое время, сезон, регламенты, людей, договоры, финансы и прогресс гонки; миграция не уничтожает старое сохранение молча.
- Трейты имеют явные условия, эффекты и порядок сочетания. Изменение временного бонуса не перезаписывает базовый навык; значения остаются в диапазоне 0–100.
- Правила Formula/GT/Endurance задавать данными и понятными обработчиками. Не превращать Endurance в Formula с другим названием: нужны экипажи/смены и гонки по времени.
- Локальные зависимости и ассеты, воспроизводимый запуск, отсутствие обязательных платных API. Сохранять лицензии зависимостей и происхождение изображений.

## Интерфейс и проверка в браузере

- Перед изменением посмотреть текущий экран и эталон. После изменения открыть приложение и проверить реальный результат, а не только JSX/CSS.
- Контрольные размеры: 1440×900 и 390×844. Таблица может прокручиваться внутри контейнера; вся страница не должна расползаться по горизонтали.
- Проверять форму, валидацию, пустую выборку, загрузку/ошибку, подтверждение, disabled, клавиатуру и возврат фокуса там, где эти состояния относятся к изменению.
- Закрытие меню/панели нажатием снаружи не активирует кнопку под ним. Верхняя панель, диалоги и мобильная нижняя навигация не обрезают содержимое.
- Важные показатели не кодируются одним цветом. Не уменьшать текст до нечитаемого размера ради размещения.
- Не подменять действие общим toast «Успешно»: успешное действие меняет наблюдаемые данные. Не оставлять активные кнопки, которые всегда отвечают «Скоро».
- Для визуального PR приложить или сохранить доступные скриншоты desktop/mobile и описать проверенные сценарии. Если браузерная проверка недоступна, прямо указать это; не писать, что она пройдена.

## Тесты и завершение задачи

Проверять реальные риски: соответствие очков нужной команде, расчёты денег, идемпотентность, сохранение/загрузка, регламенты, пит-стопы, детерминизм, последствия трейтов. Не писать тесты, которые лишь повторяют реализацию или утверждают наличие CSS-класса.

После bootstrap использовать документированные команды lint/typecheck/unit/integration/build. Для визуальных изменений добавить целевой browser smoke. Не выдавать отсутствующие команды или непроведённые проверки за существующие. CI должен оставаться быстрым: независимые задания, кэш зависимостей, короткие smoke-сценарии; длинный сезонный soak отдельно.

В PR кратко указать: проблему, что изменено, наблюдаемый результат, проверки с фактическим статусом, ограничения и ссылку на issue. Не включать чужие изменения, секреты, локальные сохранения, генерируемые сборки или идентификаторы размещения исходного Site. Не делать force push, не переписывать историю и не сливать PR без соответствующего указания пользователя.

Не объявлять issue завершённой, пока её критерии не выполнены. Если внешнее ограничение мешает, сохранить полезный результат и назвать точный незавершённый пункт. Не просить повторного разрешения на уже заказанную реализацию или обычные обратимые исправления.

## Актуальное решение: реальные данные и локальный пакет изображений

Начальная карьера основана на реальном автоспорте выбранного сезона (по умолчанию последний сезон с достаточными проверяемыми данными). Первая очередь: F1/F2/F3, GT3 и WEC; IndyCar и Formula E предусмотрены как последующее расширение регламентов, не обязательны для #3. Реальные команды, пилоты, доступный публичный персонал, поставщики, трассы, календарь и правила с источниками и датой среза. Не выдумывать неизвестные контракты или технические данные как факты: игровые оценки навыков 0–100, потенциала, трейтов и закрытых параметров явно маркировать. После старта мир развивается автономно, включая вымышленных новичков и новые организации. Исторический UI-эталон остаётся демонстрацией.

Codex должен подготовить отдельный ZIP с реальными логотипами и фотографиями из доступных правомерных источников для ручного локального импорта (не публиковать защищённые изображения в Git, PR, releases или публичных CI artifacts). Если права или доступ не позволяют включить файл, указать источник и пробел, не подменять фото вымышленным. Пакет содержит manifest с версией, стабильными ID сущностей, типом ассета, путём, источником, лицензией/условиями и SHA-256. Импорт через UI или документированную локальную команду, с проверкой схемы, размера, формата, путей ZIP (без traversal/symlink), атомарным применением и повторным импортом без дублей. Локальные пакеты и импортированные файлы исключить из Git; без пакета приложение работает с нейтральными заглушками. Не требовать платных API или скачивания изображений при каждом запуске. Подготовить ZIP вне репозитория и передать пользователю приватно, если среда позволяет; иначе предоставить локальный сборщик и точную инструкцию, явно указав, что архив не передан.


## Динамические портреты (F1 Manager)
Индивидуальная фотореалистичная голова с прозрачностью и точкой привязки, отдельный шаблон тела/одежды по профессии, маски цветов и слои эмблем/спонсоров текущей команды. Реальные лица в локальном ZIP-пакете, не в публичном Git. Согласовать ракурс, масштаб, шею и освещение; визуально проверять отсутствие эффекта приклеенной головы. При вступлении контракта в силу форма автоматически меняется во всех представлениях, лицо и ID сохраняются. Свободный агент — нейтральная одежда; процедурные новички используют тот же renderer. Исторические записи при необходимости используют команду на дату события. Не генерировать фото при трансфере. #3 — пакет, шаблоны и базовый композитинг; #5 — интеграция контрактов и регрессии трансферов, будущих контрактов, свободных агентов, персонала, отсутствия ассета и save/load.
