# Условия технической поставки

В новой карьере менеджера Mercedes карточка клиента получала из инженерной проекции только стороны и тип партнёрства. При этом коммерческая книга содержала обе даты и два разрешения. Интерфейс принимал отсутствующий флаг за отказ и выводил внутренний ключ договора.

`backend/supplier_engineering.py` возвращает четыре поля из действующей записи книги поставок для той же организации, заявки, продукта и даты. Просмотр по-прежнему проходит через ограничения проекции `backend/manufacturer/desk.py`. В стартовом каталоге без подписанного договора неизвестные условия возвращаются пустыми. Карточка и коммерческий документ различают согласованное, исключённое и неизвестное право. Кроме того, будущий договор показывается только для входящих в него заявок.

В новой карьере Mercedes начало договора показано как 1 февраля 2025 года, окончание как 1 января 2026 года. Испытания и совместная разработка предусмотрены. Для 146 сочетаний заявки и продукта в карьерах менеджера, владельца и производителя проверены даты, права, поддержка, стороны, тип партнёрства и отнесение к заявке. Все значения совпали с коммерческой книгой. [Desktop](mercedes-1366.webp) · [Mobile](mercedes-390.webp)

`Engineering.jsx` использует номер автомобиля, наименование изделия и стороны договора. В регламенте и концепции используется каталог технических правил и машин. Проверка остальных разделов выявила внутренние ключи группы компаний, инфраструктурных платежей и заводской поддержки. Их представление исправлено в `Business.jsx` и `v2/advisory-model.js`. В гараже, инженерном паспорте и реестре сохранён заводской серийный номер экземпляра. Ссылки для навигации и команды продолжают использовать неизменённые внутренние ключи. Изменения не требуют преобразования сохранений.
