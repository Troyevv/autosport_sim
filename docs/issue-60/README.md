## Как рассчитаны закрытые величины

Каждый оператор имеет один счёт. Сезонная смета суммирует вес его программ с поправками на число заявок, роль производителя и программу Hypercar. Начальный остаток составляет 67–89% сметы. Унаследованные активы поставлены на баланс один раз. Зарплаты, содержание и будущие платежи проходят по действующим журналам. Поставка внутри заводской программы имеет нулевую цену. Обслуживание клиента оплачивается тремя взносами, производство новой физической детали оформляется отдельным заказом.

Технический профиль привязан к классу, компоновке, поставщику и назначению. Расход указан в г/кВт·ч в расчётной рабочей точке. Расход теплоносителя получается из тепловой нагрузки и перепада температуры. Температурное окно, износ, интервал инспекции и прерывание тяги заданы как игровые инженерные оценки. Профиль поставщика совпадает со спецификацией на машине. Все участники монокубка используют общие физические параметры для одного изделия. Индивидуальные трейты, ранний стаж совместной работы, зарплаты, доступ консультантов, численность подразделений, уровень и состояние оборудования также моделируются. У стартовых деталей отсутствуют измерения, события производства и протоколы испытаний.

## Проверка

[Исходный аудит](baseline.md) выполнен на `c5ec684`, непосредственно после #62. Команда `uv run --locked python -m tests.opening_world manager` создаёт отдельную временную SQLite, проверяет все организации, платежи по каждому договору, совместимость всех установленных экземпляров, экспорт и воспроизведение команд. Роли для воспроизведения — `manager`, `owner`, `manufacturer`.
