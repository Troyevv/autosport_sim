# Состав пилотов и спортивные договорённости

В разделе «Пилоты и персонал → Состав пилотов» менеджер видит обещанные условия, наблюдаемые различия между заявками, доступность и претензии. Для пересмотра иерархии он выбирает экипаж и предел компенсации на человека. Каждый затронутый пилот оценивает предложение. При отказе сохраняются прежние договорённости всех участников. Расход возникает при согласии и проходит через действующий бюджет. Владелец может изучать решения своего менеджера.

В досье на вкладке «Договор» основной пилот согласует статус. Для резерва и испытаний доступны оплачиваемые назначения, совмещение обязанностей и разрешение выступать в другой серии в свободные даты. Воспитанник сохраняет академический договор. Работу на симуляторе учитывает система подготовки, завершённые испытания и практики — кадровый журнал. Зарплата начисляется по датам действующего договора.

## Границы интеграции

| Потребитель или источник | Договорённость между подсистемами |
| --- | --- |
| Инженерная система #7, #45–52 | `driver_terms.recommend` принимает подтверждённые экземпляры, сравнительный уровень спецификации и перечень допущенных заявок для каждого экземпляра. Инженерная система проверяет омологацию, совместимость, равенство поставок и закрытый парк. Рекомендация учитывает согласованный приоритет экипажа и предыдущие решения при равном статусе. Установка, состояние, износ и индивидуальная настройка принадлежат инженерной системе. |
| Наблюдения и отношения | `driver-decision` содержит конкретный вид ресурса, две заявки, основание и сведения, ставшие известными пилоту. Подтверждённое исключение имеет причину, план и срок. `driver-restored` закрывает конкретное различие по исходной ссылке. История, доверие к менеджеру, мораль и готовность обсуждать новый договор отражают последствия повторных нарушений. |
| Стратегия #21/#22, медиа #25 | `strategy_priority` принимает оценку риска, спортивную ситуацию и разрешение регламента. Кадровая система возвращает контекст для решения. Гоночные последствия и публичную реакцию создают соответствующие производители. |
| Медицина и дирекция #8/#19/#23 | `driver-absence` открывает недоступность по заключению уполномоченного источника. Прогноз возвращения информирует менеджера. Период закрывает отдельный `driver-clearance`. Несколько действующих ограничений учитываются независимо. |
| Регистрация на этап | `driver-registration` передаёт ID этапа и места, редакцию регламента, фазу, срок регистрации, состав и одобренных кандидатов. В WEC дополнительно проверяются состав экипажа и предложенный для каждого кандидата план минут за рулём с сертифицированными минимумами, максимумами и длительностью. Параметры регламента и даты индивидуальных решений поступают от дирекции. В фазе гонки кадровая замена закрыта. Смены уже заявленных членов экипажа обслуживает будущая гоночная сессия. |
| Финансы и статистика | Краткосрочная работа свободного агента получает отдельную запись в существующем журнале назначений и разовую выплату. Менеджер может снова заявить замену на следующий этап. Основной контракт продолжается. `participant` возвращает участника по месту и дате, классификация и результат связываются с его ID. Внутренние решения попадают в статистику #35 с правами соответствующей организации. |

Подтверждённые протоколы принимаются через транзакционный сервис команд. Игровой HTTP-интерфейс закрыт для команд источников. Прогноз, нехватка деталей и нажатие «Продолжить» сами по себе не создают травму или гоночный результат. В существующей карьере старые договоры получают равный приоритет при миграции. Даты, люди и проводки сохраняются, а активация фиксируется на ревизии карьеры для повторного импорта.
